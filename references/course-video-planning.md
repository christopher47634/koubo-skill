# Course Video Planning — Script Evaluation & Production Strategy

上游规划层：在执行 Mode1/Mode2/Mode3 之前，先判断脚本的制作可行性、选择生产方式。

---

## 适用场景

- 用户拿到一份课程脚本/分镜表，需要评估"怎么拍"
- 脚本格式与生产方式存在冲突（如录屏方案 vs 纯动画方案）
- 需要为一批视频选择批量生产策略（先试机一条、再铺开）

---

## 第一步：脚本格式审计

拿到脚本后，扫描分镜表中的标注，统计每种类型占比：

| 标注 | 类型 | 对应生产方式 |
|------|------|-------------|
| `[录屏]` | 屏幕录制 | 需要真人录屏，Mode1/Mode2 做不了 |
| `[实拍]` | 真人出镜 | 需要实拍素材，纯 AI 做不了 |
| `[AI生成]` | AI 动画/画面 | Mode2 (HTML动画) / Mode3 (Higgsfield) / 图像生成 |
| `[图卡/字幕]` | 文字卡片 | Mode2 最擅长 |

**关键判断**：如果 `[录屏]` + `[实拍]` 占比 > 60%，脚本不适合纯动画方案。

---

## 第二步：生产方式选择决策树

```
脚本审计 → 录屏/实拍占比？
├── > 60% → A方案：传统混合
│   ├── 录屏部分 → 真人录屏 + 后期剪辑
│   ├── 实拍部分 → 真人拍摄
│   └── 动画/图卡部分 → Mode2/Mode3 补充
├── < 30% → B方案：纯动画
│   └── Mode2 全流程（HTML动画 + edge-tts + Playwright截帧）
├── 30-60% → C方案：混合
│   ├── 概念/解释类分镜 → 动画（Mode2/Mode3）
│   └── 操作演示类分镜 → 录屏（真人录屏）
└── 用户明确指定 → 听用户的，但报告冲突
```

---

## 第三步：冲突检测 & 报告

当脚本标注与用户期望的生产方式冲突时，必须报告。不要静默忽略。

**报告模板**：
```
脚本审计结果：
- 总分镜 N 个
- [录屏] X 个（占比 Y%）
- [实拍] X 个（占比 Y%）
- [AI生成] X 个（占比 Y%）

你的方案是 [纯动画/混合/传统]，但脚本中 [录屏+实拍] 占 Y%。
建议：[具体建议]
```

---

## 第四步：课程漏斗结构

课程视频通常分两类，生产优先级不同：

### 引流视频（Lead Gen）
- 目的：吸引关注，建立人设，引流到付费课
- 时长：30-60秒
- 结构：钩子(0-3s) → 价值/演示(中段) → CTA收尾
- 关键指标：完播率 > 点赞率 > 评论率
- **先发引流、跑出数据、确认人设能涨粉，再上付费课**

### 付费课（Paid Course）
- 目的：教学，让学员学会并付费
- 时长：5-8分钟/课
- 结构：先看成品 → 步骤拆解 → 实操演示 → 作业
- 分类：概念课（口播为主）vs 实操课（录屏为主）
- 关键指标：完课率、退款率

### 生产顺序建议
1. **先做一条引流视频试机**（选概念动画占比最高的那条）
2. 跑通管线后铺开引流10条
3. 引流数据验证后再做付费课
4. 付费课先做两节样片（概念+实操各一），确认风格后批量

---

## 第五步：脚本适配检查

在进入执行前检查脚本是否适合当前生产方式：

| 检查项 | 纯动画方案 | 录屏方案 | 混合方案 |
|--------|-----------|---------|---------|
| 口播语速 | ≤150字/30s（中文极限） | ≤120字/30s（有停顿） | 按段落类型分别算 |
| 分镜密度 | 每3-5秒一个视觉变化 | 每5-8秒一个操作步骤 | 按段落类型分别算 |
| 工具演示 | 改为概念动画（损失说服力） | 录屏演示（保留说服力） | 录屏为主+动画补概念 |
| 品牌露出 | logo/图标动画 | 界面截图 | 两者混用 |

---

## 常见陷阱

1. **静默接受冲突**：脚本全是录屏但用户说纯动画，不报告就开工 → 返工
2. **改脚本不确认**：为了适配纯动画改写了分镜，但没跟用户确认 → 用户觉得"跟我想的不一样"
3. **跳过试机**：10条视频一起开工，第一条就出问题 → 全部返工
4. **忽略语速极限**：30秒塞200字，动画跟不口播 → 观众看不懂
5. **录屏分辨率不够**：小白需要看清每一步操作，模糊录屏直接导致退款
